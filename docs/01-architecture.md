## 1. Структура проекта в PyCharm

```text
trading_bot_project/
│
├── .env                      # Секреты (API_KEY, DB_PASSWORD, и т.д.)
├── docker-compose.yml        # Оркестрация: django + postgres
├── Dockerfile                # Сборка образа Django
├── requirements.txt          # Все зависимости (django, requests, psycopg2)
├── manage.py
│
├── core/                     # 🧠 Ядро системы (здесь живёт вся математика)
│   ├── __init__.py
│   ├── math_engine.py        # Расчёт вероятностей (Пуассон и др.)
│   └── settings.py
│
├── sports_data/              # 📥 Модуль сбора данных (наш новый функционал)
│   ├── __init__.py
│   ├── models.py             # Таблицы: League, MatchStat
│   ├── services.py           # Логика работы с API (FootballDataFetcher)
│   └── management/
│       └── commands/
│           └── collect_football_stats.py   # Команда для запуска сбора
│
└── execution_module/         # ⚙️ Исполнитель (взаимодействие с БК)
    ├── __init__.py
    └── bet_executor.py       # Скрипт для размещения ставок
```

## 2. Почему такая структура идеальна для нас

### 🔹 Разделение ответственности

- Если меняется **логика сбора статистики** — ты лезешь **только в `sports_data`**.
- Если меняется **математическая модель** (например, добавляем нейросеть вместо Пуассона) — ты правишь **`core/math_engine.py`**.

### 🔹 Модульность лиг

В модели `League` мы храним `api_id`.

> 💡 Когда ты захочешь добавить **Ла Лигу** или **Серию А**, тебе **не нужно менять код** — достаточно добавить запись в базу данных через **админку Django**.

Скрипт `collect_football_stats.py` **начнёт обрабатывать новую лигу автоматически**, так как он просто берёт **все активные лиги из БД**.

### 🔹 Удобство Docker

Мы запускаем весь стек одной командой:

```bash
docker-compose up
```

Скрипты, требующие **прямого доступа к системе** (например, если ты позже добавишь бота для браузера), будут лежать рядом и подключаться к **той же базе** через `localhost:5432`.

### 🔹 Как это работает в связке с PyCharm

| Возможность | Как использовать |
|---|---|
| **Навигация** | Быстро прыгать между файлами через `Ctrl+Shift+N` |
| **Отладка** | Поставить breakpoint прямо в `services.py`, запустить `collect_football_stats` в режиме отладки, и IDE остановит выполнение кода, когда получит ответ от API |
| **Инспекция данных** | «Пощупать» JSON-ответ **до того**, как он попадёт в базу |
