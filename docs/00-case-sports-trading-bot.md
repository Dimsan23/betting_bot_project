## 1. Цель проекта

Создать **автоматизированную систему**, которая:

1. **Вычисляет вероятность исхода** футбольного матча.
2. **Сравнивает её с коэффициентами букмекера** для поиска **Value Betting** — математически выгодных ставок.

---

## 2. Архитектура системы (Data Pipeline)

Система состоит из **четырёх уровней**, каждый из которых **изолирован** и выполняет **свою задачу**:

| Уровень | Название | Что делает |
|:---:|---|---|
| 1️⃣ | **Persistence** (Уровень данных) | База данных **PostgreSQL** — хранит структурированную историю матчей (`MatchStat`) |
| 2️⃣ | **Math Engine** (Уровень логики) | Модуль `core/math_engine.py`. Реализует **метод скользящего окна** — анализ только последних **N игр** (для оценки **текущей формы** команды) |
| 3️⃣ | **Analyzer** (Уровень анализа) | **Сравнение** предсказанной вероятности с **коэффициентами букмекера** |
| 4️⃣ | **Management** (Уровень исполнения) | **Кастомные команды Django** (`check_odds`), позволяющие запускать анализ из **контейнера Docker** |

### 🔄 Схема потока данных

```text
┌─────────────────────────────────────────────────────────────┐
│  1. Persistence       →  PostgreSQL (MatchStat)             │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Math Engine       →  core/math_engine.py                │
│                          (Скользящее окно: N последних игр) │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Analyzer          →  Сравнение P_bot с Odds_bookie      │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  4. Management        →  Django command: check_odds         │
└─────────────────────────────────────────────────────────────┘
```

## 3. Пошаговый алгоритм работы («Под капотом»)

Каждый раз, когда ты выполняешь команду **`check_odds`**, происходит следующее:

### 🔸 Шаг 1. Запрос к БД (ORM)

Бот делает **выборку** из таблицы `MatchStat` для команд, указанных в запросе.

Используется:
- фильтрация через **`Q`**,
- сортировка через **`order_by('-match_date')`**.

### 🔸 Шаг 2. Применение «Скользящего окна»

Мы берём **только `[:5]`** последних матчей.

> 💡 **Зачем:** чтобы исключить **«старую историю»** и оценивать только **актуальное состояние команд**.

### 🔸 Шаг 3. Вычисление среднего (λ)

Мы находим **среднее количество голов** команды в этих 5 матчах — **отдельно дома и в гостях**.

### 🔸 Шаг 4. Прогноз вероятностей

Алгоритм перебирает исходы (**счёт от 0:0 до 5:5**) и **суммирует вероятности по Пуассону**.

### 🔸 Шаг 5. Расчёт Value (Валуйности)

```text
Value = (P_bot × Odds_bookie) − 1
```

| Результат | Сигнал |
|:---:|---|
| `Value > 0` | ✅ Бот даёт **сигнал к ставке** |
| `Value <= 0` | ⚠️ Бот сигнализирует о **невыгодности события** |

## 4. Почему эта архитектура масштабируема

### 🐳 Контейнеризация

Весь этот код живёт внутри **`betting_django`**.

Если ты захочешь добавить **UI** (веб-страницу с графиками) — ты просто создашь **новый сервис** в `docker-compose`, который будет обращаться к **той же базе данных**.

### 🧩 Модульность

Мы разделили:

- **расчёты** (`math_engine`),
- **вывод результата** (`analyzer`).

> 💡 Если ты захочешь **изменить формулу прогноза** — тебе **не придётся переписывать** работу с БД.

### 🔄 Динамичность

Ты легко можешь менять параметр **`last_n`** (например, на `3` или `10`), чтобы проверить, при **какой длине «формы»** бот даёт **наиболее точные прогнозы**.
