## 1. Выполненные действия

### 🧹 Нормализация данных

Мы реализовали **слой преобразования типов** в `import_csv.py`.

| Действие | Что сделано |
|---|---|
| 📅 **Конвертация дат** | Перевели формат `DD/MM/YYYY` в стандарт **ISO 8601** (`YYYY-MM-DD`), необходимый Django для `DateTimeField` |
| 🧬 **Устранение BOM-ошибок** | Использовали кодировку `utf-8-sig` для корректного чтения заголовков CSV |
| 🗺 **Маппинг полей** | Выполнили жёсткое соответствие заголовков CSV (`Date`, `Home`, `Away`, `HG`, `AG`) с атрибутами модели `MatchStat` |
| ✅ **Валидация** | Успешно импортировано **6034 записи** в таблицу `MatchStat` |

## 4. Заметка об ошибке RuntimeWarning: naive datetime

Ты увидел предупреждение о **naive datetime**.

> ℹ️ Это **не ошибка**, а **сигнал Django**: база данных настроена на использование **часовых поясов** (`USE_TZ = True`), но импортируемые данные **не имеют информации о поясе**.

### 🔧 Техническое решение (на будущее)

В файле `import_csv.py` можно добавить `django.utils.timezone.make_aware()`, чтобы **явно сказать системе**, что `2026-05-24 00:00:00` — это время **UTC**.

> ⚠️ Но для целей **беттинга**, где важна **только дата матча**, это предупреждение **можно игнорировать**.
